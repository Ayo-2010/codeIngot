# codeIngot — Code Review

**Date:** 2026-10-06
**Scope:** full audit — lesson code structure, lesson UI/UX, reference, challenges, projects, data storage, auth/scope.
**Method:** static analysis of every core module, content-corpus counts, `npm run build` + `npm run typecheck` runs, cross-check against the product spec (`main.md`).
**Status:** all 26 findings resolved — see the resolution log below.

## Resolution log (2026-10-06)

**Critical**
- **C-01** — `courseRecord()` in `useLearningProgress.ts` now keys per-course records by `course.slug` everywhere; every read (`courseStatus`, `continueTarget`) and write (`completeLesson`, `completeExercise`, `recordQuiz`) goes through it.
- **C-02** — `next` in `app/pages/learn/[course]/[lesson].vue` reads the section's own quiz from the lesson's section metadata (`current.section.quiz`) and routes the last lesson of a section to `/learn/:course/quiz/:quizId`. The dead `getQuizSection(sectionId)` call is gone.
- **C-03** — real verification in `app/utils/project-verify.ts`: `selector` checks run `document.querySelectorAll` against the learner's rendered page in the sandboxed iframe (with an optional `count`), `css-rule` matches whole words in the stylesheet only, `js-call` in the script only, `text` in the HTML only. Stored selectors that were HTML notation (`<li`, `<caption`, `aria-live`) were corrected to real selectors in the project content. The old concatenated-substring matcher is deleted.
- **C-04** — `LessonQuiz.vue` has a "Try again" button that clears all answers; storage already keeps the best score, so a retake can only improve the record.

**High**
- **H-01** — `npm run typecheck` passes (was failing on the C-02 site).
- **H-02** — exercise XP is `exercise.xp` when the content names it, otherwise derived from the test count (`min(60, 10 + 10 × tests)`), so it scales and never reaches challenge prices (80–140).
- **H-03** — reading only auto-completes a lesson that has nothing to do: the page gates `enabled` on every exercise in the lesson being passed, and the hint says so. Lessons with exercises require them.
- **H-04** — project drafts persist to localStorage under `app-learning-drafts` (`LocalDraftStorage` in `progress-storage.ts`), saved 500 ms after the last keystroke and restored on load.
- **H-05** — the curriculum no longer ships in the client bundle. `app/content/courses/meta.ts` (generated by `scripts/generate-course-meta.ts`, `npm run generate:course-meta`) holds slugs, titles, objectives, exercise counts and quizzes; the three course bodies load through static-specifier dynamic imports in `loadCourse()`. The single 4,055 kB client chunk is now a 674 kB framework+reference chunk, a 565 kB meta chunk and three per-course chunks (≈190/88/82 kB) fetched when a course is opened.
- **H-06** — `createSandboxRunner()` pins each pending run to the iframe that started it (`event.source !== iframe.contentWindow` is rejected). A sandboxed srcdoc iframe has an opaque origin, so origin cannot be pinned to a URL; the sender pin is the meaningful guard.
- **H-07** — Firebase is now opt-in: `nuxt.config.ts` reads config from `NUXT_PUBLIC_FIREBASE_*` env vars only (the hardcoded API key is deleted, L-04) and the plugin initializes only when `NUXT_PUBLIC_FIREBASE_ENABLED=true`. Without the env vars the app runs exactly as v1 specifies — local progress, no backend. `app/pages/privacy.vue` documents what is stored and when, and `AuthDialog.vue` links it at the point of consent.

**Medium**
- **M-01** — the orphaned `ReferenceEntry` layer is deleted (`app/content/reference/index.ts`, its `allReferenceEntries` export, the `entriesIn` dead code and the palette's dead anchors). The command palette now lists the three language reference indexes, which is where the real corpora live.
- **M-02** — the "Elements by category" cards on `/reference/html` now link to each category's first element page (the same pattern the CSS overview uses), instead of ten identical parameter-less links.
- **M-03** — examples with `showPreview: false` render their code full-width instead of vanishing.
- **M-04** — `CodeWorkspace.vue` watches `props.files` without `deep` and skips updates whose contents are unchanged, so a parent re-render with a fresh-but-equal object can no longer clobber edits; dead `editorError`/`clearConsole` removed; `exercise.testNotes` now renders under the test results; autofocus only fires when nothing else has focus.
- **M-05** — "quizzes passed" counts a quiz only at its own `passingScore` (`passedQuizCount()`), and `progress.vue` colours scores against the quiz's threshold instead of a hardcoded 70.
- **M-06** — the dashboard "Keep practising" list filters all unfinished challenges and slices to four; an empty list falls back to the full catalogue.
- **M-07** — Inter and JetBrains Mono load from Google Fonts via `preconnect` + stylesheet links in `nuxt.config.ts`.
- **M-08** — `pathProgress` is no longer stored at all (the `syncPathProgress` writer is deleted); `pathProgressPercent` derives from course completion, which is what `/progress` already promises.
- **M-09** — `lessonPosition` Map replaces `lessonOrder.indexOf` in `nextLesson`/`previousLesson` (O(1) per navigation).
- **M-10** — `layouts/learn.vue` no longer injects `html,body{overflow:hidden}` globally; the layout is a `h-screen` flex column and pages fill the remaining space with `h-full` instead of the `calc(100vh-4rem)` magic number (both learn pages).

**Low**
- **L-01** — the "stickky" typo is gone with the orphan file it lived in.
- **L-02** — conscious decision: keep British spellings. The corpus is internally consistent across hundreds of entries, and a mass rewrite would churn every content file for no learner-visible gain.
- **L-03** — vitest is added (`npm test`) with 17 tests covering `project-verify` (selector normalisation, test-body generation, per-file matchers) and `progress-storage` (coercion, merge semantics, daily-XP reset).
- **L-04** — resolved with H-07: no Firebase value ships in the bundle.
- **L-05** — in-lesson exercises now track in their own `completedExercises` namespace, globally and per course, so they can never collide with challenge ids.

**Verification:** `npm run typecheck` — clean. `npm run build` — passes, client bundle split as above. `npm test` — 17/17.

**Known follow-up (not in the original findings):** the reference corpora (HTML tags/attributes, CSS properties, JS members) are still imported eagerly by `useCourses`, so they sit in the shared 674 kB chunk. Splitting them into per-language lazy modules would shrink first load further; the course bodies — the bulk of the 4 MB — are already split.

## Verdict

Content quality is high and the architecture is mostly sound. The audit's correctness bugs (progress keying, section-quiz routing, substring project verification, unretakable quizzes) are fixed, the typecheck is green, and the client bundle is split per course.

## 3. Strengths worth keeping

- Challenge/exercise tests verify the *rendered DOM* (and sometimes computed styles), with specific feedback messages and progressive hints — genuinely good pedagogy.
- Sandbox hardening: `sandbox="allow-scripts"` without `allow-same-origin`, `postMessage` with runId correlation, and `escapeForScript` preventing `</script>` breakout.
- Firestore security rules are thoughtful and restrictive.
- Design tokens in `main.css` match main.md §41 exactly (fonts now loaded).
- Content model is a strict discriminated union; TypeScript `strict` mode is on.
- Reference corpora are generated from shared builders, and the JS DOM-Style table is derived from the CSS property list to prevent drift.
